NVIDIA NIM(build.nvidia.com) 무료 AI API를 리뷰 provider로 추가

damdam6/ai-code-review-action 브랜치 feat/12-add-nvidia-nim-provider ← main 라벨 enhancement 2026-08-08

1요약

NVIDIA NIM의 OpenAI 호환 API(https://integrate.api.nvidia.com/v1)를 7번째 리뷰 provider nvidia로 추가한다. 최근 z.ai(GLM) provider를 추가한 커밋 3377a19(#9)과 완전히 동일한 11개 파일 패턴을 따르며, 신규 provider 파일 없이 기존 createOpenAICompatible 팩토리에 baseURL case 하나를 추가하는 작업이다. 엔드포인트는 플래너가 라이브로 검증 완료(/v1/models가 200 응답), 문서에 넣을 예시 모델 ID도 실제 카탈로그에서 확인했다.

2현황 분석

provider 등록은 5개 지점에 분산되어 있고, 현재 어디에도 nvidia가 없다:

  • 타입/검증 — src/providers/base.ts:67의 ProviderName 유니온, src/types.ts:124의 AgentConfig.provider 유니온, src/config.ts:8의 VALID_PROVIDERS(검증 실패 시 src/config.ts:56에서 "Must be one of" 에러).
  • 팩토리 — src/providers/base.ts:69-89의 createProvider switch. kimi/deepseek/zai는 createOpenAICompatible(src/providers/openai-compatible.ts:11-47)에 baseURL만 넘긴다. 이 팩토리는 openai SDK로 chat.completions.create를 호출하며 max_tokens 기본 4096, 타임아웃 180초 + 429/timeout 재시도 3회(src/providers/base.ts:12-23)를 이미 갖추고 있다.
  • API 키 배선 — src/dispatcher.ts:31-38의 API_KEY_MAP이 provider명 → env 변수명을 매핑. action.yml이 inputs.*-api-key → ::add-mask:: → env로 전달하고, .github/workflows/workflow.yml·templates/workflow.yml이 secrets.*를 입력에 연결.
  • 모델 지정 — 모델은 ai-review-agents.yml의 자유 문자열로 provider와 분리되어 있어(params.model이 그대로 전달, src/providers/openai-compatible.ts:31) 모델 관련 코드 작업은 없다. 이슈 메모와 일치.
  • 빌드 — npm run build(tsc + ncc)로 dist/index.js를 커밋하는 방식. zai 커밋에서 dist diff는 소스 변경분 5라인뿐이었다.

3설계

채택안: z.ai 패턴 그대로 복제. createProvider에 case "nvidia"를 추가해 createOpenAICompatible(apiKey, { name: "NVIDIA", baseURL: "https://integrate.api.nvidia.com/v1" })를 반환한다. NIM은 표준 max_tokens를 지원하므로 useMaxCompletionTokens는 쓰지 않는다(OpenAI case 전용). env 변수는 NVIDIA_API_KEY, action 입력은 nvidia-api-key.

엔드포인트 검증(이슈의 플래너 확인 항목): https://integrate.api.nvidia.com/v1/models가 인증 없이 200을 반환하며 OpenAI 호환 모델 목록을 제공함을 2026-08-08에 확인했다. 단, 이슈 본문의 예시 중 meta/llama-3.1-405b-instruct와 deepseek-ai/deepseek-r1은 현재 카탈로그에 없으므로, 문서에는 라이브 검증된 ID를 쓴다: meta/llama-3.3-70b-instruct, nvidia/llama-3.1-nemotron-70b-instruct, nvidia/llama-3.3-nemotron-super-49b-v1.5, openai/gpt-oss-120b, deepseek-ai/deepseek-v4-flash-0731.

기각안: ① 별도 src/providers/nvidia.ts 파일 — OpenAI 호환이라 기존 팩토리로 충분, 불필요한 분기. ② NVIDIA 모델 ID 화이트리스트 검증 — 모델을 provider와 분리된 자유 문자열로 두는 기존 설계와 충돌하고 카탈로그 변동에 취약. 문서로만 안내한다.

4작업 단계

  1. ProviderName 유니온에 "nvidia" 추가(67행), createProvider switch에 case "nvidia" — baseURL https://integrate.api.nvidia.com/v1, name NVIDIA (zai case 옆 78행 부근) src/providers/base.ts
  2. VALID_PROVIDERS(8행)와 AgentConfig.provider 유니온(124행)에 nvidia 추가 src/config.ts, src/types.ts
  3. API_KEY_MAP에 nvidia: 'NVIDIA_API_KEY' 추가(37행 zai 다음) src/dispatcher.ts
  4. nvidia-api-key 입력 정의 + ::add-mask::$NVIDIA_API_KEY 라인 + NVIDIA_API_KEY: ${{ inputs.nvidia-api-key }} env 배선 — 기존 6개 키와 같은 3개 지점 action.yml
  5. 두 워크플로에 nvidia-api-key: ${{ secrets.NVIDIA_API_KEY }} 입력 배선 .github/workflows/workflow.yml, templates/workflow.yml
  6. README: secrets 등록 예시(76행 뒤)에 gh secret set NVIDIA_API_KEY 추가, provider 표(106행 뒤)에 NVIDIA NIM 행 추가(예시 모델은 검증된 ID, "OpenAI 호환" 표기) README.md
  7. setup-guide: secrets 블록에 NVIDIA 추가, provider 유니온 표기(46행)에 nvidia 추가, 그리고 NVIDIA 모델 ID 형식 섹션 신설 — 네임스페이스/모델명 형식 설명, 검증된 예시 모델 목록, build.nvidia.com에서 키 발급·모델 탐색 안내, 무료 티어 rate limit 주의 docs/setup-guide.md
  8. zai 테스트(71-77행)와 같은 패턴으로 "accepts nvidia as a valid provider" 테스트 추가 tests/unit/config.test.ts
  9. npm run build로 dist/index.js 재빌드 후 diff가 소스 변경분만인지 확인, npm test 전체 통과 확인, 커밋(repo 스타일: feat: add NVIDIA NIM as a review provider, Closes #12) dist/index.js ✓ dist diff는 소스 변경분 4줄. 신규 nvidia 테스트 포함 45개 통과. orchestrator 테스트 3개 실패는 stash 후 재실행으로 main에서도 동일하게 실패함을 확인 — 이 이슈와 무관한 기존 실패(별도 이슈 대상).

5리스크

리스크영향완화책
NIM 무료 티어의 낮은 rate limit(분당 요청 제한) 에이전트 다수를 nvidia로 지정하면 429 발생 가능 src/providers/base.ts:16-17의 기존 재시도 로직이 429를 지수 백오프로 3회 재시도. setup-guide에 무료 티어 주의 문구 명시
reasoning 계열 모델이 <think> 블록을 응답 본문에 포함 리뷰 코멘트에 사고 과정이 그대로 노출될 수 있음 코드 변경 없이 문서에서 instruct 계열 모델 사용 권장
이슈 본문의 예시 모델 일부가 현재 카탈로그에 없음(405b, deepseek-r1) 문서를 이슈 그대로 옮기면 사용자가 404 모델 에러를 겪음 2026-08-08 라이브 카탈로그에서 검증한 ID로만 문서화(설계 섹션 목록)
dist/index.js 재빌드 diff 오염 의존성 변동 시 diff가 커져 리뷰가 어려워짐 ncc 버전이 고정돼 있고 zai 커밋에서 5라인만 변경됐음. 빌드 후 diff를 확인하고 소스 변경분 외 diff가 크면 보고
